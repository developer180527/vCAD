### What the scheme turned out to be

Faces are named by provenance; **edges and vertices are named by the set of faces they
bound**. Change a box's width and OCCT renumbers everything, but the top face is still the
top face, so the edge {ZMax, YMin} is still that edge. Face identity is the only thing that
has to be tracked through operations — and faces are exactly what OCCT's reports cover best.

Two things this cost that were not obvious up front:

1. **Boundary names must carry no feature serial.** A boundary name is a pure function of
   its bounding faces' names. Stamping the current feature on it gives the same edge a
   different name in the box than in the fillet result, breaking every reference on the next
   operation. Found by the sweep test.
2. **`BRepPrimAPI_MakeBox::FrontFace()` is the x = dx face, not y = 0**, and `LeftFace()` is
   y = 0. Our `BoxFace` enum is therefore axis-named (`ZMax`, `YMin`, …) rather than passing
   OCCT's misleading names through. Found because a test targeted the wrong edge and the
   naming layer correctly told us so.
3. **`ShapeUpgrade_UnifySameDomain` is not a `BRepBuilderAPI_MakeShape`.** It reports through
   `BRepTools_History`, and that history is the only way to learn which faces merged —
   geometric matching cannot recover it, since a merged face has neither the area nor the
   centroid of either parent. `Operation` carries both mechanisms behind one accessor.
4. **Display precision is a correctness concern, not cosmetics.** Formatting a length with
   four decimals in metres loses 44 microns, so copying a value out of a field and pasting
   it back would move the model. `format()` picks per-system defaults that keep one digit
   below a micron.
5. **A `HealingReport` counting only faces and edges lies about structural damage.** An
   unclosed shell has zero invalid faces and zero invalid edges; the report now says so in
   words instead of printing "0 faces and 0 edges".

### Exit criterion

`tests/acceptance/m1_naming_stability.cpp` passes, including all four adversarial cases
(split, vanish, merge, cross-process determinism), under ASan, on all three desktop
platforms.

**Status: COMPLETE.** Green on all three desktop platforms as of 2026-08-12
(run 31574520520): 20 C++ test cases / 713 assertions, 24 Rust tests, 9 Python tests,
clean under ASan + UBSan on Linux.

The cross-platform work turned up five real portability defects, none of which macOS could
have shown:

| Defect | Platform | Why only there |
|---|---|---|
| PE exports no symbols without `__declspec(dllexport)` | Windows | ELF and Mach-O export everything by default; the DLL built fine and every consumer failed to link. |
| `M_PI` is not standard C++ | Windows | MSVC hides it behind `_USE_MATH_DEFINES`. Now `std::numbers::pi`. |
| `popen`/`pclose` are `_popen`/`_pclose`; `cmd.exe` has no `VAR=x cmd` prefix | Windows | The determinism test spawns a subprocess. |
| pybind11's `--cmakedir` returns a native path | Windows | CMake read `C:\hostedtoolcache` backslashes as escapes. |
| `std::atomic` used without `<atomic>` in assetlib | Linux | libc++ and MSVC's STL provide it transitively; libstdc++ does not. |

Everything in the deliverables list above is done except the two items explicitly deferred
(asymmetric chamfer, BLAKE3 in place of the FNV placeholder), both recorded there.

The determinism case is the one people skip. Don't — without it the DDC produces
cross-machine misses and the shared cache tier is worthless. Non-determinism almost always
enters through pointer-ordered iteration of OCCT maps.

### Explicitly NOT in M1

No document model, no recompute engine, no DDC integration, no renderer, no UI, no Python.
M1 is a library that turns parameters into named topology and can prove it stays named.
