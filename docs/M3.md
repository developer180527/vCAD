# M3 — Renderer

Design: [ADR 0007](decisions/0007-renderer-seam.md). Read that first; this is the plan.

## The shape of it

```
core ──▶ render/tessellate ──▶ render/scene ──▶ ┃ IGpuResources ┃ ──▶ GPU
                                                ┃ IFrameSink    ┃
                                                ┃ IPicker       ┃
         └─────────── ours, permanently ──────┘ └── swappable ──┘
```

Above the seam is where the CAD-specific value lives: element naming into vertex attributes,
exact edge polylines from OCCT, section planes, content-addressed mesh caching. Below it is
the bgfx backend and a null backend for CI.

The seam is **not** for swapping in the game engine's renderer — that requirement was
withdrawn (see the amendment in ADR 0007). It survives because CI has no GPU and the iPad
needs a separate Metal backend, so a second implementation exists from day one either way.

**Everything here is sized for 100k–1M parts.** That single requirement rules out a draw call
per part and makes content-addressed dedupe load-bearing rather than an optimisation: a
100k-part assembly is overwhelmingly repeated fasteners and fittings, so it holds perhaps
1000 *unique* shapes. One mesh per unique shape, instanced.

## Milestones

Each has a binary acceptance test, as with M1 and M2.

### M3.1 — Tessellation and the mesh cache — **DONE**

Green on macOS: 9 Rust acceptance tests. Three things the work turned up:

1. **`BRepTools::Clean` before meshing is mandatory.** OCCT stores triangulation *on* the
   shape and `BRepMesh_IncrementalMesh` keeps an existing one it deems adequate — so
   re-tessellating with a finer angular tolerance silently returns the coarse mesh. The
   symptom is nastier than a plain bug: the cache correctly registers a miss and hands back
   identical geometry, so a display-quality setting appears to work and does nothing. The
   angular-tolerance test caught it asserting more triangles and getting 48 = 48.
2. **`abi/` was in the wrong layer.** It sat in `core/abi` for two milestones; the moment it
   needed a renderer header, `check_layering.py` fired. The rule was right and the placement
   was wrong — the ABI is the facade over core *and* render, so it now lives at the top level
   with its own layer rules.
3. **A double free the compiler could not see.** The session held the `DdcCache` in a
   `unique_ptr` *and* handed it to the `TieredCache`. Compiled perfectly; would have crashed on
   session release. Found by reading it back, not by a tool.

#### Original scope (2–3 weeks)

`Shape` → `RenderMesh`, cached in the DDC.

- `BRepMesh_IncrementalMesh` for triangles; `BRepAdaptor_Curve` sampling for exact edge
  polylines (**not** derived from the triangle mesh — that is what makes edges crisp).
- Per-face and per-edge ranges carrying an element index, so a GPU pick resolves to a stable
  `ElementName`.
- Content hash = shape hash + settings digest. Cached in the same `recompute::Cache` as
  cooked features: tessellation is exactly the derived data a DDC exists for.
- Serialisation into the DDC blob format, alongside the existing shape+element-map encoding.

**Acceptance** (Rust, through the ABI): tessellate a 30-feature part; assert triangle count
is stable across runs, every face maps to an `ElementName` that resolves, edge polylines exist
for every edge, and a second session sharing the DDC directory hits the cache instead of
re-tessellating. A deflection change must miss. And the one that matters for scale: **N
identical parts must tessellate once**, not N times.

### M3.2 — Scene assembly and the null backend (2 weeks)

`Document` → `SceneFrame`, plus the backend that needs no GPU.

- Diff against the previous frame; upload only what changed. Dragging a dimension on a
  40k-face assembly must not re-upload the assembly.
- Camera: orbit, pan, zoom, zoom-to-fit, and **orthographic** — engineers check alignment in
  ortho, and perspective makes coincident faces ambiguous.
- Navigation presets (SolidWorks / Fusion / FreeCAD). People are religious about this and it
  is cheap to offer.
- `NullBackend`: implements all three interfaces by recording draw calls.

**Acceptance**: the whole scene layer is tested in CI **without a GPU** via `NullBackend` —
draw-call counts, upload counts across an edit, correct element→highlight mapping, and that a
no-op frame uploads nothing. This is why the seam is three narrow interfaces rather than one.

### M3.3 — bgfx backend (3–4 weeks)

The first thing that looks like a CAD application.

- bgfx init on Metal / D3D12 / Vulkan; shaders via `shaderc` into the build.
- Shaded pass + edge pass with depth bias so edges sit on surfaces without z-fighting.
- SSAO, and order-independent-ish transparency for section caps.
- **GPU ID-buffer picking**: render element ids to an offscreen target, read back one pixel.
  Box/lasso select falls out for free. Far simpler and faster than CPU ray casting against
  B-rep.

**Acceptance**: 1M triangles at 60fps with correct edges; pick latency under 5ms; a golden-image
suite with a perceptual diff, run locally (CI runners have no GPU — see below).

### M3.4 — Scale: culling, LOD and budget (3 weeks)

What makes 100k–1M parts actually work, beyond dedupe and instancing.

- GPU-driven frustum culling; occlusion culling via a depth pyramid.
- LOD selection per instance by screen-space size; small-feature culling (a part covering a
  few pixels draws as a box, or not at all).
- A live-memory budget with eviction to coarser LOD, so a pathological assembly degrades
  instead of exhausting memory.

**Acceptance**: a synthetic 250k-instance assembly holds 60fps; draw calls stay proportional
to *unique* meshes rather than instances; resident memory stays under a declared budget.

## Constraints that shape the work

**No GPU in CI.** GitHub runners have no GPU, which is why `NullBackend` is an M3.2
deliverable rather than an afterthought: it makes the scene layer — where the logic bugs live
— fully testable. Pixel-level regression needs a software rasteriser (lavapipe on Linux) and
is deferred until there is something stable worth pixel-diffing.

**Layering still applies.** `render/` may include bgfx; `core/` may not, and
`tools/check_layering.py` enforces it on every build. The renderer must never become a reason
for GPU types to appear in `core/` — that would end the iPad port.

**iPad.** The seam is POD-only by construction, so a C facade over it for the SwiftUI shell is
mechanical. Not built in M3; not designed out either.

**Budget.** 8–10 weeks. M3.3 is most of it, and a good CAD viewport is the most visible
quality signal in the product.

## Deliberately not in M3

Ambient occlusion beyond SSAO, shadows, PBR materials, IBL, anything cel-shaded. All of that
arrives free with the engine renderer, and none of it is what makes a CAD viewport good.
Edges, picking and orthographic accuracy are.
